## 1. Purpose & Context

The Morning Brief is an AI-generated daily operational summary — a "newsletter for your business" that includes overnight financial highlights, trending signals worth acting on, top-performing content, suggested priority actions, and operational warnings. Designed for a 2-3 minute scan to start the creator's workday with complete situational awareness.

### User Story
> As a creator managing commerce, content, and platforms, I want a daily AI summary of what happened overnight — orders, trending topics, content performance — so I can start my day with the right priorities.

### Business Goals
- Increase DAU by establishing a daily check-in habit (push → open → brief → act)
- Surface trends and opportunities before competitors (time-sensitive intelligence)
- Drive downstream actions: script approvals, engagement responses, publish decisions
- Reduce time-to-insight by aggregating data from 6+ modules into one screen
- Increase product tag and publish rates through suggested actions

### When This Screen Is Used
- **Morning routine**: Push notification at user-configured time (default 6:30 AM) → open app → brief
- **On-demand**: Dashboard widget "☀ Xem Briefing hôm nay" → this page
- **Email fallback**: Brief also sent as email (same content, formatted for email client)
- **Catch-up**: Missed a day → view past briefs via `/daily-brief?date=2026-03-26`

### Entry Points
- Push notification: Morning push at configured time → deep link
- Dashboard ([W001]): "☀ Xem Briefing hôm nay" card
- Email: Brief email → "Xem chi tiết" CTA → deep link
- Sidebar: Home → "☀ Briefing" (conditional — only visible after brief is generated)
- Direct URL: `/daily-brief` (today) or `/daily-brief?date=YYYY-MM-DD`

### Exit Points
- "Xem chi tiết P&L →" → `/finance/profit` (Profit Dashboard W071)
- "Tạo ý tưởng →" → `/ideas/new?from_trend_id=[id]` (Idea Board)
- "Xem chi tiết →" (trend) → `/intelligence/trends/[id]` (Trend Detail W027)
- "📊 Analytics" → `/analytics/posts/[post_id]` (Post Analytics)
- "🔄 Tạo phiên bản mới" → `/content/derivatives/new?source=[id]`
- "Duyệt →" → `/scripts?filter=pending` (Script List filtered)
- "Inbox →" → `/inbox?filter=urgent` (Unified Inbox filtered)
- "Queue →" → `/publish/queue` (Publish Queue)
- "Kiểm tra →" → `/settings/diagnostics` or relevant settings
- "Nạp thêm →" → `/settings/credits` (Credit Purchase)

## 2. Preconditions / Postconditions

### Preconditions
- User authenticated with valid session
- Workspace has at least 1 day of activity data (otherwise shows first-day welcome)
- Brief has been generated by daily cron job (6:30 AM UTC+7 default)
- User has `workspace:billing:read` permission

### Postconditions
- Brief view logged via analytics (`brief.viewed`)
- CTA clicks tracked for action conversion analysis
- Brief marked as "read" for push notification badge clearing
- If email sent: email delivery tracked in `notification_logs`

## 5. Displayed Data / Data Binding

| UI Element | Data Source | API | Display Format | Cache |
|---|---|---|---|---|
| AI summary text | `daily_briefs.summary_text` | `BriefService/GetBrief(date)` | Natural-language paragraph (2-3 sentences) | Pre-computed (cron) |
| AI confidence score | `daily_briefs.confidence_score` | Same | "92%" badge | Pre-computed |
| Revenue yesterday | `analytics_snapshots.revenue WHERE date=yesterday` | `ProfitService/GetSummary(date)` | "5.2M VND ↑18%" | Pre-computed |
| Costs | `analytics_snapshots.costs` | Same | "1.8M VND" | Pre-computed |
| Net profit | Computed: revenue - costs | Same | "3.4M VND (65%)" | Pre-computed |
| Order count | `orders.count WHERE date=yesterday` | Same | "12 đơn mới" | Pre-computed |
| Pending refunds | `refunds WHERE status='pending'` | Same | "2 đơn hoàn tiền chờ xử lý" | Pre-computed |
| Top trends | `trends ORDER BY growth_rate DESC LIMIT 3` | `TrendService/List(sort=growth, limit=3)` | Trend items with growth % | `trend:hot:{wid}` 1h TTL |
| Trend fit score | AI-computed relevance to creator's niche | `CopilotService/Query(trend_fit)` | "🟢 High / 🟡 Medium" | Pre-computed |
| Top content | `content_performance ORDER BY er DESC LIMIT 1 WHERE period=24h` | ClickHouse query via `AnalyticsService/GetTopContent` | Post card with metrics | Pre-computed |
| Suggested actions | Aggregation: pending approvals + urgent threads + ready-to-publish | `BriefService/GetSuggestedActions` | Prioritized action list | Pre-computed |
| Warnings | `diagnostics_records` + `CreditService/GetBalance` projection | `BriefService/GetWarnings` | Warning items with fix CTAs | Pre-computed |

## 7. States / State Machine

| State | Condition | Visual |
|---|---|---|
| LOADING | Page load, fetching brief | Newsletter skeleton: 6 section placeholders with shimmer |
| LOADED | Brief available | Full newsletter layout with all sections populated |

## 11. Error Handling

| Error Type | Trigger | UI Response | Recovery |
|---|---|---|---|
| Brief not generated yet | Cron hasn't run (early morning) | "☀️ Briefing đang được tạo... (~1 phút)" | Auto-retry after 30s |
| Brief generation failed | AI service error during cron | "Không tạo được briefing hôm nay. [Thử tạo lại] [📧 Nhận bản tóm tắt qua email]" | Manual retry or email fallback |
| Finance data unavailable | Finance service down | Section shows: "💰 Dữ liệu tài chính chưa sẵn sàng." (section degradation, other sections still show) | Section auto-retries |
| Trend data stale | Trend API failed overnight | Section shows: "🔥 Xu hướng: đang cập nhật..." | Auto-refresh |
| Send email fails | Email service error | Toast: "Không gửi được email. [Thử lại]" | Retry |
| Past brief not found | No brief for requested date | "Không có briefing cho ngày {date}. [← Xem ngày gần nhất có brief]" | Navigate to nearest available brief |
| Network error | No internet | Full-page: "Không tải được briefing. [Thử lại]" | Retry |

## 13. Loading Behavior

| Stage | Duration | Visual |
|---|---|---|
| Shell render | 0ms | App Shell renders (SSR). Header with date visible. |
| Skeleton phase | 0-200ms | Newsletter layout with 6 section skeletons (shimmer) |
| AI Summary | 100-300ms | Summary card appears first (highest priority) |
| Finance section | 150-500ms | Numbers animate from 0 to value with counter animation |
| Trends section | 200-600ms | Trend items slide in with staggered animation (100ms apart) |
| Top content | 300-700ms | Thumbnail loads lazily, metrics animate in |
| Actions + Warnings | 400-800ms | Lower-priority sections populate last |

### Cadence Effect
Sections appear top-to-bottom with 100ms stagger, creating a "reading" animation — inviting the user to scan downward naturally.

## 14. Performance Requirements

| Metric | Target | Measurement |
|---|---|---|
| LCP | < 1.5s | AI Summary card (most important content, above fold) |
| FID | < 100ms | First CTA click |
| CLS | < 0.05 | No layout shift (pre-computed brief means known layout) |
| TTI | < 2.0s | All CTA buttons interactive |
| Brief loading | < 500ms | Pre-computed content from cache (cron generates at 6:30 AM) |

> **Note**: Morning Brief is pre-computed by cron, not generated on-demand. This means loading is essentially a cache read + render — should be extremely fast.

## 15. Real-time Updates

| Data | Method | Frequency |
|---|---|---|
| Brief content | None (pre-computed by cron) | Once per day at configured time |
| Suggested action counts | None (stale is OK — snapshot from cron time) | N/A |

### Why No Real-time
The Morning Brief is intentionally a **snapshot** — a "newspaper" for the day. It does NOT update in real-time because:
1. Consistency: The brief should read the same way at 7 AM and 2 PM
2. Simplicity: Newsletter format is inherently static
3. Performance: Pre-computed = instant load

## 16. Localization Notes

- Primary language: Vietnamese
- Currency: VND compact format ("5.2M", "1.8M", "3.4M") — with "VND" suffix on first mention, then implicit
- Percentages: "18%", "65%", "8.2%" — comma for decimals in body text ("8,2%") but dot in badges
- Date: "Thứ 5, 27/3/2026" (Vietnamese day name + DD/MM/YYYY)
- Time: "6:30 sáng" (12h format with Vietnamese period)
- Growth indicators: "↑18%" (positive), "↓5%" (negative) with color

## 19. Technical Implementation Notes

### SvelteKit Specifics
- **Route**: `src/routes/(app)/daily-brief/+page.svelte`
- **Server load**: `+page.server.ts` → fetch pre-computed brief from `daily_briefs` table
- **URL params**: `?date=2026-03-27` for past briefs (default = today)

### Data Fetching Strategy
```
+page.server.ts:
  const date = url.searchParams.get('date') || today()
  const brief = await briefService.getBrief(workspaceId, date)
  // Brief is pre-computed — this is a cache read, not computation

  if (!brief) {
    // Check if cron is still running
    const status = await briefService.getGenerationStatus(workspaceId, date)
    return { brief: null, status } // GENERATING or NOT_FOUND
  }
  return { brief }
```

### Pre-computation (Cron Job)
- Runs daily at user-configured time (default 6:30 AM UTC+7)
- Aggregates data from: ProfitService, TrendService, AnalyticsService, ContentService, DiagnosticsService
- AI summary generated via `CopilotService/Query(mode=analytics, scope=brief)`
- Result stored in `daily_briefs` table with TTL = 30 days
- Parallel: sends email version via `NotificationService/SendBriefEmail`

### Intersection Observer for Section Analytics
```
onMount:
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(e => {
      if (e.isIntersecting) trackSectionViewed(e.target.dataset.section)
    })
  }, { threshold: 0.5 })
  
  document.querySelectorAll('[data-section]').forEach(el => observer.observe(el))
```
